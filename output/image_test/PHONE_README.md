# 六色墨水屏 NFC 整图测试

需要先烧录 r5.1 图片测试固件：colors-wait-nfc-image-r5.1-ftm。r4 只支持简单指令。

手机发送文件：

- nfc_sixcolor_test_01.bin：图1，28,832字节；像素CRC32为97224EB2。
- nfc_sixcolor_test_02.bin：图2，28,832字节；像素CRC32为A598D107。
- *_preview.png：按实际发送像素生成的放大预览，屏幕的真实颜色会有差异。

## 操作

1. 板子保持外接3.3V，等待开机六色色块刷新完成。
2. 将图片.bin文件复制到手机Download文件夹。
3. ST25 NFC Tap识别标签后，在左上角菜单的“通道管理”中开启Mailbox。如果FTM页面自动开启，可直接继续。固件已设置MB_MODE允许开启；开机时Mailbox暂时关闭，便于保留原来的EEPROM指令功能。
4. 进入“ST25DV演示 → FTM演示 → 固件更新 / Firmware Update”。选择nfc_sixcolor_test_01.bin。这里借用App的二进制文件传输，MCU接到的是图片，只放RAM，不执行固件升级。
5. 如提示演示口令，输入12345678。它是传输演示口令，不是标签配置密码。保持“Error recovery / 错误恢复”开启，然后开始传输。
6. 文件传完后，程序检查格式、尺寸、像素编码、文件头CRC和整图CRC。手机读取成功应答后才开始刷屏。保持供电，等待约30多秒，以屏幕BUSY完成为准。
7. 图1成功后用同样方法发送图2，检查编号和图案是否改变。不需要复位MCU。

如果旧版App的文件选择器为空，可将.bin放到Download/bintouploadforstSt25FWU文件夹后重试。具体路径以已安装App的文件选择界面为准。

不要使用“将文件写入存储器”发送整图：那是512字节EEPROM。本包通过256字节Mailbox循环传输，由MCU保留完整28,800字节像素。

## 看结果

手机传输成功与屏幕刷新成功是两个阶段。接收完成但校验失败不会刷新；中途断场超时15秒会中止并关闭Mailbox，原屏幕画面保留。重新开启Mailbox并从头发送即可。

重新测试原先的1234五次字节写入前，在“通道管理”关闭Mailbox。Mailbox开启时EEPROM写入会被芯片禁止。

固件也实现了ST Light命令06的完整文件读回。FTM页面的“从标签接收数据”可用于后续读回测试；App是否支持保存到文件以实际界面为准。保存后可在PC运行：

    python tools/check_image_file.py 读回文件.bin

主机软件仿真已验证完整收发、CRC错误重传、重复分包、超长/损坏包拒绝及与屏幕SPI像素流一致。实际手机传输与屏幕效果需实板确认。首轮继续使用外接3.3V，线圈供电整图传输尚未验证。

2026-11-14实板结果：r5.1通过ST-Link烧录及读回校验；用户确认图1传输后显示IMAGE 1，再不复位发送图2，成功显示IMAGE 2。手机到板子的整图连续刷新通过。文件读回目前只完成软件仿真。
