# 同一手机供电与通信时的复位排查

用户反馈：只用独立供电线圈整流供电，磁场来自读写 NFC 的同一部手机；自动色块、UID 显示后，在等待输入时又回到启动画面。

源码检查结果：没有无命令超时复位、没有软件复位调用、没有启动 IWDG/WWDG。HardFault 进入死循环并置 fault，不主动复位。等待使用普通 WFI/Sleep，不进入 Stop/Standby。硬件选项字节是否启用看门狗，应在实板另行读取，不能仅凭源码排除。

优先怀疑手机在发现标签、切换 NFC 会话或操作页面时断场/间歇发场，或者无线取能与负载不匹配导致 3.3V 下陷。两个线圈仍共享同一手机的 RF 场，供电线圈独立并不构成连续供电保证；这里的供电来自单独线圈，不是 ST25DV 的 V_EH 输出。ST 关于手机磁场可能反复开关的说明同样适用于这条能量来源。

此为待验证假设，没有示波器数据，尚不能确定复位原因。上电两次自动刷新会在每次恢复供电后重新执行，因此掉电恢复可能表现为重复色块→UID。

## 本次诊断固件

新增 g_debug.reset_flags，在 main 最开始保存 RCC_CSR，再设置 RMVF 清除粘滞复位标志，供下一次启动区分来源。未增加自动复位、未更改选项字节，也未移除用户要求的启动显示。

| reset_flags 按位与掩码非零 | 含义 |
|---|---|
| 0x08000000 | PWRRSTF，电源相关复位；首次正常上电也会出现，不单独证明异常掉压 |
| 0x10000000 | SFTRSTF，软件复位 |
| 0x20000000 | IWDGRSTF，独立看门狗 |
| 0x40000000 | WWDGRSTF，窗口看门狗 |
| 0x04000000 | PINRSTF，复位脚；可与其他标志同时出现，需结合波形判断 |
| 0x80000000 | LPWRRSTF，低功耗管理相关复位 |

必须按位解读，不能比较整个寄存器只等于一个掩码。当前没有检测到 ST-Link，诊断固件仅编译和仿真通过，未下载、未读到用户本次实际复位标志。Debug Flash 36,016 B，Release Flash 33,548 B，RAM 链接占用 2,136 B。

## 下一步验证

1. 先恢复此前外部稳定 3.3V 的测试接法并隔离线圈电源输出，保持无命令等待数分钟。若不再复位，优先查无线供电。
2. 只用线圈供电时，用示波器同步观察 MCU 旁 3.3V、PW_IN，必要时 NRST；在刚显示 UID、切入 App 写入页面、等待、写入时观察。万用表平均值不能排除短暂跌落。
3. 下载诊断固件并读取 reset_flags，辅助区分电源、复位脚和看门狗。ST-Link 的 3.3V 输出不可混入测试；否则可能掩盖无线供电问题。
4. 若确认供电问题，再根据实测能量、断场时间、峰值电流设计储能、稳压、电源就绪门限及低功耗；不能只加固定软件延时就假定解决。独立供电发射器可帮助分离“手机通信”与“持续供电”两个变量。
