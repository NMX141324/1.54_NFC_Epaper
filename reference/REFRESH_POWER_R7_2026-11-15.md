# r7 / APP 1.4：刷新完成回执与断电后屏幕复位

## 现象与判断

用户补充：故障为偶发；纯手机线圈供电；传完开始刷新后移开手机，再贴回可能继续闪动、反复变化或显示乱码。本轮未连接 ST-Link，没有采集 3.3V、RESET、BUSY 或升压轨波形。

代码能够确认：

1. r6/r6.1 没有断电续传、复位重刷上一张图、超时主动复位或失败自动重刷逻辑。图像只存 RAM，启动重新建立旧 EEPROM 命令序号基线，不重放旧命令。
2. 旧 APP 在收到图片接收回执后结束 NFC 连接，屏幕当时可能仍在刷新。它没有等待刷屏结束，连接结束可能改变手机 RF 场行为；具体是否导致这块板掉压尚未实测。
3. 旧固件上电立即释放屏幕 RESET；MCU 与屏幕控制器在电压下降时不一定同步复位，因此不能把重新上电时的画面变化理解为正常恢复上一张图。
4. 旧驱动刷新结束只需一次 BUSY 空闲采样。短暂电平跳变可能使程序提前关屏幕电源、休眠并切换空闲灯；此前没有过滤这种跳变。
5. PA1 刷屏灯由 SysTick 维持，正常只在驱动返回后熄灭；IRQ 不会自行切成空闲。提前熄灭可能来自驱动提前返回、报错返回、MCU 复位或电源本身变化，不能只凭灯光认定哪一种。

上述是已确认的软件缺口与可解释路径，不是已经测出这次偶发故障的唯一根因。刷新需要持续、合格的电源；CRC 成功证明接收的数据完整，不证明屏幕升压或波形供电正常。断电中断的全彩刷新不能按“继续传剩下部分”恢复，应重新发送并完整刷新。

## 固件 r7

- 每次 MCU 启动先将 PA6 / 屏幕 RESET 保持低，空闲不释放；只有显式刷新任务才执行复位、释放 RESET 和完整初始化。启动无色条、UID、旧图自动刷新。
- 刷新 BUSY 必须连续空闲 200ms；关电 BUSY 连续空闲 50ms，才进入后续阶段。不会反转 BUSY 极性或忽略超时。
- 刷新阶段异常短于 1000ms 报错 -10，不把它作为成功；该阈值是异常检查，不是厂家规定的最短刷新时间，更不是用固定延时替代 BUSY。
- 所有驱动失败路径保持屏幕 RESET，保留错误阶段，不自动重刷。
- PA1 从新图任务开始（包括必要的连续刷新休息）保持到驱动结束；驱动报错后闪烁提示。PA0 空闲短闪、传输快闪。结果回执发送时可能短暂显示传输指示。
- 新增调试字段 refresh_active/start/end、BUSY 刷新时间、过滤的跳变次数、RESET 保持状态。

上电保持 RESET 是 MCU 运行后的保护；MCU 尚未运行或电压不合格时，不能仅靠软件保证引脚/升压行为。若仍有 MCU 未复位但屏幕供电掉压的情况，需通过外接稳定 3.3V 对照及示波器继续查供电、储能和 RESET 硬件。当前没有 ADC 电压日志，因此不能断言已经测到或排除了欠压。

## APP 1.4 与新完成协议

必须配合 r7。APP 1.4 先检查握手 capability bit0，旧固件提示升级，防止把旧回执当作完成。r7 仍保留命令 04/05，兼容 ST25 NFC Tap 和旧 APP 的图片传输，但这些旧客户端仍不等待新的完成回执。

新上传命令为 `09 + E6IM`，文件仍是原来的 28832 字节，颜色和双 CRC 格式不变。

| 回执 | 发送时机 | 手机行为 |
|---|---|---|
| `40 02 89 81` | 图像已完整接收、校验，准备执行刷屏 | 显示“正在刷新屏幕”，维持 NFC 连接，不能显示刷新成功 |
| `40 16 89 90 ...` | 驱动完成 BUSY 检查、关电和休眠，返回 0 | 核对图片 ID/CRC，再显示“刷新完成”和耗时；触感反馈遵循手机设置 |
| `40 16 89 91 ...` | 驱动报错 | 显示刷屏失败和错误码 |

完成包总长 24 字节：`40 16 89 状态`，随后小端 image_id、pixel_crc32、elapsed_ms、int32 error、reset_flags 各 4 字节。reset_flags 是该次启动的 RCC_CSR 快照，不应独立当成“刷新中发生过复位”的证明。

APP 在等刷屏结果时每 250ms 检查 Mailbox，最长等 330 秒，覆盖驱动各阶段的有界等待。此时 100% 仅表示数据传完，界面另有等待指示。收到本图成功完成包后才关闭连接并显示“刷新完成”。这个结果证明 MCU 所观察到的数字 BUSY/驱动流程完成，不是对画面颜色的光学检测。

断连、Mailbox 关闭、回执不匹配、驱动失败或等待超时均不会自动重传图片。停止等待不等于撤销已启动的物理波形，界面会提醒继续供电。新命令在尚未调度刷屏前会话关闭时也不会启动屏幕任务。

## 验证

- APP 27 项 JVM 测试全部通过；APK 和 Android Lint 任务通过，保留原项目依赖的 Lint 警告。
- 测试涵盖 0F 退避、完整图片传输、收图后尚不能判完成、35 秒刷屏等待、错误码、错误图片回执、刷新中失去供电状态、330 秒有界超时、无自动重发及旧固件拒绝。
- Cortex-M0+ 模拟通过：上电 RESET 保持且无 SPI/旧图重放；BUSY 20/100ms 短暂空闲不提前关电；异常短刷新拒绝；新命令接收/完成/失败及无 IRQ 软件触发完成发送。
- Kotlin 实际生成的命令 09 分包进入真实 C 接收器，核对全部 28800 字节显示像素，并在屏幕驱动返回后核对完成回执中的图片 ID/CRC。
- Debug Flash 44940 B；Release Flash 38792 B；RAM 均为 32384 B，包含链接器预留堆栈与堆。
- 本轮没有安装到手机或烧录硬件，没有新的线圈供电实测结果。

## 使用与对照

1. 用 ST-Link 烧录 `epaper_NFC_r7_refresh_result.hex`，手机覆盖安装 `epaper_nfc_app_1_4.apk`。这两项需要一起升级。
2. 上电保持原画面，不自动修复中断后残留的画面。重新点击发送，贴近后持续供电，直到手机弹出“刷新完成”。
3. 刷新中拿开手机时，应将该次操作视为失败/结果未确认；再次贴回不应由 MCU 自动重放旧图，需要重新发送完整图像。
4. 先用隔离线圈输出后的稳定外接 3.3V 连续测试，再测纯线圈。若手机提示完成但屏幕仍明显闪动，记录耗时与画面，并测 BUSY、电源和 RESET；不要仅增加固定等待时间掩盖问题。

屏幕指令依据用户提供并保存在 `reference/vendor/main/GDEH0154E01_idf.c` 的正常 OTP 流程；没有引入测试波形、自动翻转 BUSY 或忽略 BUSY。[厂家产品与资料入口](https://www.good-display.com/product/983.html)。
